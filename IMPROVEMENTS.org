* Activity feed
** DONE Show author names in activity feed entries
:PROPERTIES:
:COMMIT: f2e6ff2
:END:

The ~activity.feed~ API provides ~author_user_id~ only in the ~:message~
sub-field. For ~thread_v2~ and ~dm~ activity types, data comes from
~bundle_payload~ instead, so ~(plist-get m :author_user_id)~ returned nil and
~(format "%s" nil)~ produced the string ~"nil"~.

Fixed by: using ~when-let~ in the parser so ~author-id~ stays nil, then at
render time falling back to the fetched message's ~user~ slot. Also added
type-specific prefixes ("Mentioned in", "Invited to").

** DONE Reuse ~slack-message-to-string~ for activity feed rendering
:PROPERTIES:
:COMMIT: 8e603c9
:END:

The activity feed had its own message rendering (custom header, ~slack-message-body~
only) that was inconsistent with channel buffers. Now it delegates to
~slack-message-to-string~ — the same function channels use — and just prepends an
activity context line ("Thread in #channel", "Mentioned in #ops-team", etc.).

This gives activity entries: profile images, colored author names, attachments,
reactions, thread info, and all future rendering improvements for free.

~generic_system_alert~ ("Alert in"), ~external_channel_invite~ /
~shared_workspace_invite~ ("Invited to"), ~external_dm_invite~ ("DM invite
from"). Updated both ~slack-buffer-insert~ and
~slack-activity-message-to-string~ for consistency.

*** API response structure by type

From the live response, no ~actors~ field exists in the API data. The Slack
desktop app derives actor names ("Maria and 3 others") from locally cached
thread participants, not from the ~activity.feed~ endpoint.

~thread_v2~:
#+begin_src json
{"type": "thread_v2", "bundle_info": {"payload": {"thread_entry": {
    "channel_id": "...", "latest_ts": "...", "thread_ts": "...",
    "unread_msg_count": 0}}}}
#+end_src

~dm~:
#+begin_src json
{"type": "dm", "bundle_info": {"payload": {"dm_entry": {
    "latest_message": {"ts": "...", "channel": "..."}}}}}
#+end_src

~at_user~, ~at_user_group~, ~internal_channel_invite~:
#+begin_src json
{"type": "at_user", "message": {"ts": "...", "channel": "...",
    "is_broadcast": false, "thread_ts": "...",
    "author_user_id": "U06J3JGAXH8"}}
#+end_src

~message_reaction~:
#+begin_src json
{"type": "message_reaction", "message": {"ts": "...", "channel": "..."},
    "reaction": {"user": "U06J3JGAXH8", "name": "+1"}}
#+end_src

** LATER Show reactor as actor for message_reaction activities

Slack's activity feed shows the person who reacted as the card's author (e.g.
"Patrick — Reacted in #seo") and quotes the reacted-to message as context.
Emacs currently shows the reacted-to message with its original author (e.g.
"Pablo Stafforini — I'll set it up...") and appends "Patrick reacted with :+1:"
below.

To match Slack's presentation, ~message_reaction~ activities need a custom
rendering path instead of delegating to ~slack-message-to-string~:

1. Context header: "Reacted in #seo" (use reactor's name, not message author)
2. Actor line: reactor's avatar + name (from ~activity-reaction.user~)
3. Quoted message: the reacted-to message body (truncated, as context)
4. Reaction emoji display

This requires either a separate branch in ~slack-buffer-insert~ for reaction
activities, or a wrapper around ~slack-message-to-string~ that replaces the
header.

** DONE Improve unread indicator styling

Replaced ~"*"~ / ~" "~ prefix with a Unicode filled circle (~●~) propertized
with a new ~slack-activity-unread-face~ (bold, golden foreground) for clear
visual distinction between read and unread entries.

** DONE Fix 5-10 second delay when opening the activity feed

Added ~slack-activity-feed--prefetch-messages~: after parsing the activity feed
API response and before rendering, it collects all ~(ts, channel, thread-ts)~
tuples, checks which messages are already cached, and fires parallel async
~conversations.history~ / ~conversations.replies~ requests for uncached ones.
A counter tracks completion; once all requests finish, the buffer renders.

Since all messages are now in cache by render time,
~slack-message-get-or-fetch~ returns immediately for every item, eliminating
the 5-10 second freeze from 20 sequential synchronous API calls.

* DONE Channel loading delay / background prefetch
:PROPERTIES:
:SEVERITY: high
:END:

Added ~slack-prefetch-unread-channels~ in ~slack-websocket.el~: after WebSocket
connection (both initial and reconnect), it waits 5 seconds for counts to
arrive, then fires staggered async ~conversations.history~ requests (1.2s apart,
~50 req/min tier 3) for channels with unreads and no cached messages. Controlled
by ~slack-prefetch-channel-messages-p~ defcustom (default ~t~).

Chose the lighter alternative: only prefetch channels with unreads, not all
channels, to minimize memory and rate-limit impact.

* DONE Stale reaction cache
:PROPERTIES:
:FILE: slack-reaction-event.el
:END:

Implemented option 4 (selective refresh): when ~slack-event-find-message~ for a
reaction event finds the room but the message is not in cache, it now calls
~slack-reaction-event--fetch-and-cache-message~ which fetches the single message
via ~conversations.history~ with ~latest=ts, inclusive=true, limit=1~ and pushes
it into the room's message cache. The reaction is then applied to the freshly
cached message rather than being silently dropped.

* DONE Synchronous blocking calls
:PROPERTIES:
:FILE: slack-message.el, slack-stars-buffer.el
:COMMIT: b19cd04
:END:

Added ~slack-stars--prefetch-messages~ to ~slack-stars-buffer.el~: fires parallel
async API requests for all uncached saved-item messages, then invokes a callback
once all are ready.  Refactored ~slack-buffer-init-buffer~,
~slack-buffer-insert-history~, ~slack-buffer-update-oldest~, and
~slack-buffer--replace~ to use cache lookups instead of the blocking
~slack-message-get-or-fetch~.

Also fixed ~slack-buffer--replace~ which was fetching ALL star items just to find
one by ts — now looks up only the needed item.

~slack-message-get-or-fetch~ still exists for edge cases but all bulk callers
(activity feed and stars buffer) now use async prefetch.

* DONE WebSocket event handling gaps
:PROPERTIES:
:FILE: slack-websocket.el

** DONE Missing or silently dropped events

Added a catch-all ~t~ clause to the WebSocket event dispatcher that logs
unhandled event types at debug level via ~slack-log~, so unknown events are
no longer silently dropped.

All previously unhandled events are now covered:
- ~app_mention~ — routed through the message handler (identical payload).
- ~app_rate_limited~ — logs at warning level.
- ~update_thread_state~ — updates thread counts, modeline, and logs channel/ts
  details at debug level.

** DONE Reconnection fragility

Added exponential backoff to WebSocket reconnection in ~slack-team-ws.el~:
delay starts at 2 seconds, doubles each attempt (capped at 120s), and resets
on successful connection. New slots: ~reconnect-after-sec-base~ (2),
~reconnect-after-sec-max~ (120). Methods: ~slack-ws-reconnect-backoff~,
~slack-ws-reconnect-reset-backoff~.

Also added ~app_rate_limited~ WebSocket event handler that logs rate limit
notifications from Slack.

* DONE Token handling fragility
:PROPERTIES:
:FILE: slack-request.el
:COMMIT: 21527e0
:END:

Replaced the hard-coded endpoint-to-token list with a self-healing cache
(~slack-token-preference~ hash table).  Pre-seeded with the same known endpoints,
but now self-corrects at runtime: when Slack returns ~team_is_restricted~ or
~enterprise_is_restricted~, the cache is updated and the request retried once
with the other token.

Also consolidated the activity feed's manual token selection to use the shared
~slack-select-token~ function.

* DONE Missing nil checks and silent error suppression
:PROPERTIES:
:SEVERITY: medium
:END:

Replaced all four ~ignore-errors~ sites with ~condition-case~ + ~message~ logging:

- ~slack-activity-feed-buffer.el~ — room name lookup (both instances)
- ~slack-message-formatter.el~ — file summary
- ~slack-block.el~ — confirmation dialog creation
- ~slack-message-reaction.el~ — reaction at point lookup

* DONE Image cache unbounded
:PROPERTIES:
:FILE: slack-image.el
:END:

Added ~slack-image-cleanup~ interactive command that deletes cached images older
than ~slack-image-cache-max-age-days~ (default 30) from both
~slack-image-file-directory~ and ~slack-profile-image-file-directory~. Reports
number of files deleted and space freed.

* DONE Mark-as-read optimistic update
:PROPERTIES:
:FILE: slack-message-buffer.el
:END:

~slack-buffer-update-mark-request~ now saves the previous ~last-read~ value
before the optimistic update. ~slack-conversations-mark~ accepts an optional
error callback; on failure, the callback reverts ~last-read~ and refreshes the
marker overlay.

* DONE Block types not implemented
:PROPERTIES:
:FILE: slack-block.el
:END:

Implemented ~file~ and ~input~ block types in ~slack-block.el~:

- ~slack-file-layout-block~: renders as ~[File: <external-id>]~ for remote file
  references.
- ~slack-input-layout-block~: renders label (bold) + optional hint + "[interactive
  input]" marker. Parses ~label~, ~hint~, ~optional~, and ~dispatch_action~
  fields.

Both have ~slack-block-to-string~ and ~slack-block-to-mrkdwn~ methods.

* DONE Rate limiting not abstracted
:PROPERTIES:
:FILE: slack-util.el, slack-conversations.el
:END:

Added ~slack-rate-limit-delay~ and supporting infrastructure to ~slack-util.el~:
- ~slack-rate-limit-tiers~ alist defines tier 1-4 request-per-minute limits.
- ~slack-rate-limit-counters~ hash table tracks request counts per tier with
  sliding 60-second windows.
- ~slack-rate-limit-delay~ returns 0 if under limit, or seconds to wait if at
  limit.
- ~slack-rate-limit-reset~ clears a tier's counter.

Updated ~slack-conversations-list~ to use ~(slack-rate-limit-delay 'tier-2)~
instead of the hard-coded modulo-20 check.

* DONE Slack thread URLs should open in Emacs

Added ~slack-browse-url~ which parses Slack permalink URLs using the existing
~slack-permalink-to-info~, finds the team by domain via
~slack-team-find-by-domain~, and navigates via ~slack-open-message~. Falls back
to the default browser if the team isn't connected or parsing fails.

Registered automatically as a ~browse-url-handlers~ entry matching
~*.slack.com/archives/*~ URLs. Controlled by ~slack-intercept-urls~ defcustom
(default ~t~).

* DONE DM "no message" after selecting unread room

Two root causes:

1. ~slack-conversations-success-handler~ silently dropped the ~on-success~
   callback when the API response contained a warning other than
   ~already_in_channel~. Benign warnings like ~missing_charset~ would prevent
   the buffer from ever being created. Fixed by always calling ~on-success~
   after logging the warning.

2. ~slack-room-display~ called ~conversations.history~ directly for DMs, but
   dormant/closed DMs require ~conversations.open~ first. Fixed by adding a
   ~slack-im-p~ check that calls ~conversations.open~ before fetching history,
   matching the pattern used by ~slack-im-open~.
